# PLAN

## Одна фраза

Тот, кто собирает базу знаний для бота или ИИ-продавца, за полчаса получает из своей переписки с клиентами разбор частых вопросов и ответов. Правит его руками и одной фразой собирает из него документ для базы знаний.

## Похожие проекты (поиск 05.11.2026, `gh search repos`)

- Выгрузка чатов Telegram (tnjd/telegram-export, 485 звёзд; maiakanegae/telegram-export-converter, 79): только выгружают, без разбора.
- Генераторы FAQ (upstash/faq-generator, 84): делают FAQ по документации, а не по переписке с клиентами.
- Анализаторы WhatsApp (atteol/WhatsAnalyzer, 1): только статистика.
- По запросам «chat to faq», «telegram chat export faq», «база знаний переписка», «chat2faq» ничего не нашлось.

Вывод: есть слабые аналоги. Отличие: разбор под базу знаний бота, правка человеком между разбором и сборкой, личные данные скрываются до того, как переписку видит агент, всё по-русски.

## Вертикальный срез

1. Человек выгружает чат из Telegram Desktop в JSON. Ставит плагин одной командой.
2. Пишет агенту: «разбери переписку ‹путь к result.json›».
3. Скрипт без агента читает выгрузку и выкидывает стикеры и служебные сообщения. Телефоны, почты, @ники и имена участников он заменяет на «Владелец» и «Клиент 1, 2…». Агент спрашивает, кто из участников — сам человек.
4. Агент пишет `razbor.md`: сводка, темы по частоте, как спрашивают, все ответы с датами, пометки «ответа нет», «ответы расходятся», «ответ старше трёх месяцев», вопросы без ответа. У каждой темы стоит «☐ в базу».
5. Человек правит ответы и ставит «☑».
6. Пишет: «собери базу знаний из razbor.md». Проверка перед сборкой: нет отмеченных тем без ответа, нет нерешённых расхождений, нет телефонов и почт. Агент пишет `baza-znaniy.md`, в нём только отмеченное.

Как проверить, что сработало: в `baza-znaniy.md` только темы с «☑», ответы дословно как после правки, нет ни одного телефона, почты и @ника.

## Чего в первой версии нет

- ВК и Битрикс24 по API, файлы Excel (.xlsx), CSV, где весь диалог лежит в одной ячейке.
- Голосовые, картинки и видео не читаются, только подсчитываются.
- Имена людей внутри текста, которые не участвуют в переписке, скрываются не всегда: файл нужно проверить глазами.
- Проверка на Codex: в первой версии только Claude Code.

## Источники первой версии

Telegram (JSON из Telegram Desktop), WhatsApp (.txt, «Экспорт чата»), CSV из CRM, где одна строка — одно сообщение. Перед разбором CSV агент показывает колонки и спрашивает, где автор, дата и текст.

## Число до выпуска

Число успеха: ‹черновик, ждёт подтверждения владельца› не меньше трёх посторонних людей поставят плагин и получат `razbor.md` из своей переписки за две недели после выпуска. Считаю по сообщениям и задачам (Issues) репозитория.

## Задачи

1. Учебные переписки, выдуманные, без настоящих людей: Telegram JSON, WhatsApp (iPhone и Android), CSV с точкой с запятой в кодировке Windows-1251.
2. Скрипт `razobrat.py`: три читателя → общий вид, маскировка, роли, подсчёт пропущенного, режим `--info`. Тесты пишутся раньше кода, запускаются на Python 3.9 и 3.13.
3. Скилл разбора: `SKILL.md` по документации Claude Code, шаблон `razbor.md`.
4. Скрипт `proverit.py` для проверки перед сборкой, тоже тесты раньше кода.
5. Скилл сборки: `SKILL.md`.
6. Плагин: `plugin.json`, `marketplace.json`, проверка `claude plugin validate --strict .`, установка у себя.
7. README, LICENSE (MIT), описание и topics.
8. Прогон на настоящей переписке владельца: файл лежит в `private/`, в репозиторий не идёт.
9. Тест у постороннего, правки, релиз v0.1.0.
